* What banna Assigns

banna is the single authority for the names and numbers BISOS services bind to. Each is
assigned once and never recomputed, so a new entry never moves an existing one, and each
registry rejects duplicates when it is imported.

| Registry                | Module          | Assigns                                                         |
|-------------------------+-----------------+-----------------------------------------------------------------|
| TCP ports               | =tcpPorts.py=   | =portNu= per service; and, for those with a =.here= name, its   |
|                         |                 | =hereIp= (=127.0.22.x=) and =hereName= (defaults to =portName=) |
| Unix sockets            | =unixSockets.py= | RPyC socket numbers                                            |
| System accounts         | =sysAccts.py=   | =uid=/=gid= of every account a BISOS capability creates         |

** TCP ports and =.here= names

Code looks a port up rather than hardcoding it:
=tcpPorts.tcpPortsAssignedList.tcpPortsList['kafka'].portNu=. A port with a =hereIp= gets a
line in =/etc/hosts=, generated by =bannaForEtcHosts= and installed by =bisos.dnsCap=. The
IP is stored with the port (since 2026-10-09; before, it was derived from sorted position, so
adding a port could renumber others). =hereName= lets a port publish another name: =kafka.here=
is Kafbat UI's port (=kafbatUi=, 24009), not the broker's. =hereIpOf(name)= returns the IP
without needing =/etc/hosts= to be current.

** System accounts (uid/gid)

=useradd -r= picks numbers per host, so the same account differs between platforms, and files
moved between them (backups, rsync, cloned VMs, NFS) or logs disagree. =sysAccts.py= assigns
them from 500 upward (inside Debian's dynamic system range, without changing
=/etc/login.defs=: =adduser --system= counts up from 100 and =useradd -r= down from 999):
airflow 501, kafka 503, prometheus 504, grafana 505, the qmail block 510--519. =useraddScript(acctName)= is the bash an sbom
runs: it creates the account with its numbers, warns if an existing account differs, and
refuses if a number is already taken.

** Commands

#+begin_src bash
bannaInfo.cs -i bannaForEtcHosts       # the /etc/hosts block: hereIp  hereName.here  # port=
bannaInfo.cs -i bannaForEtcPasswd      # /etc/passwd lines of every registered account
bannaInfo.cs -i bannaForEtcGroup       # /etc/group lines of their primary groups
bannaInfo.cs -i bannaSysAcctsVerify    # read-only: this host's accounts against the registry
#+end_src

* Installation

The sources for the  bisos.banna pip package is maintained at:
https://github.com/bisos-pip/banna.

The bisos.banna pip package is available at PYPI as
https://pypi.org/project/bisos.banna

You can install bisos.banna with pip or pipx.

** Installation With pip

If you need access to bisos.banna as a python module, you can install it with pip:

#+begin_src bash
pip install bisos.banna
#+end_src

** Installation With pipx

If you only need access to bisos.banna as a command on command-line, you can install it with pipx:

#+begin_src bash
pipx install bisos.banna
#+end_src

The following commands are made available:
- seedBanna.cs
- exmpl-banna.cs

Layered on top of Debian, *BISOS*: (By* Internet Services Operating System) is a
unified and universal framework for developing both internet services and
software-service continuums that use internet services. See [[https://github.com/bxGenesis/start][Bootstrapping
ByStar, BISOS and Blee]] for information about getting started with BISOS.\\
*BISOS* is a foundation for *The Libre-Halaal ByStar Digital Ecosystem* which is
described as a cure for losses of autonomy and privacy in a book titled: [[https://github.com/bxplpc/120033][Nature
of Polyexistentials]]
